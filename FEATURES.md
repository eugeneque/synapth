# Synapth — функционал и заложенные возможности

Synapth — маркетплейс навыков, инструментов и MCP-серверов для ИИ-агентов, построенный на Next.js 15. Он собирает навыки с GitHub и внешних реестров, проверяет их на безопасность и выдаёт каждому готовую команду установки. Агент может сам найти и подключить навык через API, без браузера. Вокруг каталога — соцслой для авторов и подписки Synapth Pro. Код разделён на серверное ядро `cortex/`, клиентский слой `axon/` и изоморфные утилиты `lib/`.

## Что уже работает

### 1. Каталог «навыков»

Всё, что можно подключить агенту, хранится как одна сущность `Skill` трёх категорий ([types/skill.ts](types/skill.ts)):

- **MCP** — MCP-сервер, локальный (stdio) или удалённый (SSE);
- **Prompt** — фрагмент системного промпта или `SKILL.md`;
- **Tool** — HTTP-эндпоинт с описанием инструментов для function calling.

У каждого навыка есть манифест: системный промпт, инструменты с JSON Schema, способ запуска, запрашиваемые права (network, filesystem, shell, env, clipboard), нужные переменные окружения и схема шагов исполнения (`flow`). Источник записи — GitHub или «On Synapth» (`skillSource()`).

### 2. Сбор навыков (автокраулер)

[cortex/crawler.ts](cortex/crawler.ts), [cortex/crawl-jobs.ts](cortex/crawl-jobs.ts), [cortex/crawl-sources.ts](cortex/crawl-sources.ts), [lib/github-parser.ts](lib/github-parser.ts):

- **Источники кандидатов**: GitHub (темы, code search по `SKILL.md`), MCP registry, npm, Docker MCP, известные маркетплейсы (`KNOWN_MARKETPLACES`). Внешние источники только поставляют GitHub-репозитории — импорт всегда идёт через `github-parser`. Awesome-списки не парсятся из-за лицензий.
- **Разбор репозитория**: `synapth.json`, `mcp-server.json`, `server.json` (MCP registry), `.mcp.json`, `tool.json`, коллекции `SKILL.md`, а если ничего нет — README с явными признаками навыка.
- **Расписание**: каждые 2 ч по сетке UTC. На Netlify — scheduled function `crawl-cron.mjs` → `POST /api/cron/crawl` (bearer `SYNAPTH_CRON_SECRET`), под `next start` — таймер из `instrumentation.ts`. Каждый проход — GitHub + один внешний источник по очереди, сортировка stars/updated чередуется.
- **Журнал**: каждый запуск пишется в `CrawlRun`; зависшие записи закрываются автоматически. Ошибка одного репозитория не роняет обход; rate limit GitHub отличается от 403.
- **Ручной запуск**: `npm run crawl`, панель в админ-панели (право `crawler.run`) или `POST /api/v1/crawl`. Один репозиторий — `/api/v1/import/github`. Импорт не перезаписывает навык с чужим автором.

### 3. Проверка безопасности (Sandbox Scanner)

[lib/sandbox-scanner.ts](lib/sandbox-scanner.ts) проверяет манифест по каталогу правил из ТЗ: 9 групп, 62 правила (`RULE_CATALOG`). У каждого — уровень, метод и статус: **30 `active`**, **16 `partial`** (статическое приближение полного метода), **16 `planned`**. Версия набора правил (`RULES_VERSION`) пишется в каждый отчёт.

- **PI-\*** — инъекции в промпты и отравление инструментов: переопределение инструкций (en/ru/zh), скрытый текст (нулевая ширина, Unicode Tags, bidi, HTML-комментарии), закодированные вставки (base64/hex/URL — декодируются и сканируются повторно), затенение чужих инструментов, сокрытие от пользователя, автозапуск, аномальная длина.
- **EX-\*** — утечка данных: приказ отправить данные на адрес, ссылки/картинки с данными в параметрах, приёмники (вебхуки, боты, туннели), параметры, выманивающие контекст.
- **MC-\*** — опасное исполнение: `curl | sh`, реверс-шеллы, `eval`/`pickle`, `shell=True`, деструктивные команды, закрепление в системе, обфускация, `sudo`, майнинг (→ Карантин).
- **SK-\*** — секреты (OpenAI/Anthropic, Yandex Cloud, GigaChat, AWS, GitHub, Slack, Google, Telegram, PEM, строки БД; энтропия > 4,5). Живые ключи блокируют публикацию.
- **OP-\*, ST-\*, RM-\*** — права (опасные сочетания), структура (невалидный манифест → Отклонён, `npx pkg` без версии, выдача себя за бренд, бинарники, лицензия), удалённые серверы без TLS.
- **DP-\*** — цепочка поставки: [lib/dependency-scanner.ts](lib/dependency-scanner.ts) (install-скрипты, тайпосквоттинг, нет lock-файла, dependency confusion) и [cortex/dependency-audit.ts](cortex/dependency-audit.ts) (уязвимости из OSV, молодые и непопулярные пакеты). Краулер и импорт собирают снимок в `GithubSource.audit`.

Оценка риска — `max(0, 100 − 60·crit − 25·high − 8·med − 2·low)`, но исход решают правила, а не баллы (`decideOutcome`).

### 4. Уровни доверия и модерация

- **Навыки**: `Quarantine < Sandbox < Community < Verified < Gov` ([types/trust.ts](types/trust.ts)). `Rejected` — исход скана, а не уровень: такая версия не публикуется. `Quarantine` хранится, но скрыт из поиска, списков, API и агентов.
- **Паки (скиллсеты)**: `Sandbox < Community < Certified < Gov`, уровень производный (`packTrust()`).
- **Verified** сканер не ставит никогда — только модератор через `reviewed: true` и только при оценке ≥ 85. Новая версия наследует Verified/Gov, если не изменились права, промпты и описания инструментов (`inheritLevel()`).
- **Модерация по заявкам** ([cortex/moderation.ts](cortex/moderation.ts)): кнопка «Отправить на модерацию» на странице записи → заявка (одна открытая на запись) → уведомление модераторам → разбор на `/dashboard/moderation/[id]` (манифест, README, перезапуск сканера, вердикт) → уведомление автору. Отклонение требует комментарий.

### 5. Поиск и сортировка

- **Свой поисковый движок** без внешних сервисов ([cortex/search.ts](cortex/search.ts)): BM25F с весами полей, стемминг, автодополнение, исправление опечаток, фасеты, подсветка совпадений.
- **Язык запросов**: `category:MCP is:verified lang:python author:… tag:… stars:>100 price:free "фраза" -слово`.
- **Сортировки** ([cortex/ranking.ts](cortex/ranking.ts)): Trending (скорость установок × звёзды × удержание), Hidden Gems (Verified, удержание ≥ 60 %, ≤ 5k установок), Recent, Relevance.
- **Страница `/search`** — дом каталога и людей: вкладки `all | people | skills | skillsets`, фильтр источника `github | synapth`, слайдер избранного на нетронутых вкладках. `/explore`, `/people`, `/skillsets` — редиректы.
- **Глобальный поиск** в хедере (⌘K, [cortex/global-search.ts](cortex/global-search.ts)): смешанная выдача людей, навыков и скиллсетов прямо в мега-панели меню.

### 6. API для агентов (AI-first)

Одни и те же операции по двум транспортам ([cortex/agent.ts](cortex/agent.ts)):

- **MCP-сервер `synapth-mcp`** — `POST /mcp` (Streamable HTTP, stateless JSON-RPC: `initialize`, `tools/list`, `tools/call`).
- **REST** — `GET|POST /api/v1/agent/<tool>`, список инструментов — `GET /api/v1/agent`.
- **Обнаружение** — `/.well-known/synapth.json` (адреса, аутентификация, публичный ключ подписи) и `/llms.txt`.

Инструменты: `search` (без ключа — 30/мин с IP, без Sandbox), `resolve_task` (до 3 вариантов: пак ≥ 80 % покрытия, жадный набор в бюджете токенов без конфликтов, одиночный навык; формула 0,45·rel + 0,2·trust + 0,2·success + 0,1·retention − 0,05·tokens/budget; подбор — BM25F), `get_skill`, `get_pack`, `fetch_skill` (файлы с SHA-256, `contentHash`, подпись Ed25519), `install_plan`, `confirm_install` (сверка хешей → `integrity_mismatch`), `report_outcome` (раз в сутки; ключи младше 7 дней и ключи автора не влияют на рейтинг), `check_updates` (diff прав, `revoked`), `execute`.

Политика ключа применяется до поиска; каждый ответ несёт `pol`, каждая ошибка — код и подсказку агенту; `requiresApproval` + серверная `approvalCard` — ничего не ставится молча. Текст задачи считается недоверенным (`scanUntrustedText`). Каждый вызов пишется в `AgentAuditLog` (журнал в «Публикация и ключи»).

### 7. API-ключи

[cortex/api-keys.ts](cortex/api-keys.ts): ключи `sk_live_<32>`, в базе только SHA-256. Scope — `catalog:read`, `skills:fetch`, `skills:execute`, `packs:write`; срок 30/90/180/365 дней; отзыв мгновенный. Политика ключа может только ужесточать политику владельца (`tightenPolicy`). Лимит активных ключей зависит от тарифа. Заголовок `X-Agent-Name` подписывает вызовы в журнале, но прав не даёт.

### 8. Установка в один клик

[axon/install.ts](axon/install.ts) генерирует команду установки под четыре клиента: Claude Code, Claude Desktop, Cursor и curl.

- **MCP** → `claude mcp add …` или JSON для `mcpServers`.
- **`SKILL.md` из GitHub** → `npx degit` в `.claude/skills/` или `.cursor/skills/`.
- **Промпт** → файл `SKILL.md` или правило `.cursor/rules/*.mdc`.
- **HTTP-инструмент** → вызов через платёжный шлюз.
- **Скиллсет целиком** → `curl -fsSL …/api/v1/skillsets/<slug>/install?target=claude-code|cursor | sh`. Все данные манифестов экранируются (`shellQuote()`), Sandbox-записи и HTTP-инструменты в скрипт не попадают.

Выбранный клиент запоминается в настройках аккаунта и cookie.

### 9. Оплата за каждый вызов

[cortex/gateway.ts](cortex/gateway.ts) и `POST /api/v1/skills/:id/execute` (или `execute` в MCP):

- **Проверки до списания**: не Sandbox/Карантин, scope `skills:execute`, политика ключа, лимит на вызов и в сутки, аргументы по JSON Schema инструмента, баланс. Отказ ничего не стоит.
- **Резерв → списание или снятие резерва** ([cortex/billing.ts](cortex/billing.ts)): `hold` при открытии; на 2xx — `release` + три проводки (списание, доход автору, комиссия 15 %), иначе только `release`. Сумма проводок операции — ноль, баланс = сумма проводок. Деньги — целые микродоллары.
- **`Idempotency-Key`**: повтор в течение 24 ч возвращает сохранённый ответ без повторного списания ([cortex/idempotency.ts](cortex/idempotency.ts)).
- **Шлюз**: только публичные адреса (`safeFetch`), таймаут 30 с, ответ до 1 МБ; тело чужой ошибки наружу не отдаётся.
- В `UsageEvent` пишутся ключ, статус апстрима, задержка и размер ответа. Комиссии копятся на системном аккаунте `usr_platform`.

### 10. Synapth Pro: тарифы и оплата

- **Страница `/pro`** — Free / Pro / Team / Business (месяц или год), разовые проверки, лицензии On-prem ([types/billing.ts](types/billing.ts)).
- **Кабинет `/dashboard/billing`** — текущий тариф, расход квот за сутки, смена тарифа (выше — сразу с пропорциональным пересчётом, ниже — со следующего периода), отмена/возобновление, пополнение кошелька, история оплат.
- **Платёжные шлюзы** ([cortex/payment-providers.ts](cortex/payment-providers.ts)): ЮKassa (карта, СБП, сохранённый способ для продления, вебхук перепроверяется запросом в API), CloudPayments (HMAC вебхуков), mock-страница для разработки. Применение платежа идемпотентно ([cortex/payments.ts](cortex/payments.ts)).
- **Продление** — `POST /api/cron/billing` (Netlify: `billing-cron.mjs`, раз в сутки): списание сохранённым способом, иначе `past_due` → 14 дней льготы → Free.
- **Квоты тарифа** ([cortex/plans.ts](cortex/plans.ts)): ключи, запросы агента и `resolve_task` в сутки, срок хранения журнала.

- README в markdown;
- граф исполнения (trigger → tools → decision → output);

### 12. Аккаунты, роли и верификация

- **Регистрация и вход** ([cortex/registration.ts](cortex/registration.ts), Auth.js v5): пароль (bcrypt) с подтверждением почты 6-значным кодом (Resend), GitHub и Google. Пользователь, кошелёк и приветственный кредит создаются одной вставкой. Хендлы проверяются на зарезервированные слова.
- **Роли**: `user < moderator < admin`, права — `PERMISSIONS`/`can()` ([types/auth.ts](types/auth.ts)), проверяются по роли из стора, а не из JWT. Первый админ — `npm run role -- <email|handle> admin`. Публично админ показывается как `user`.
- **Флаг `developer`** (не роль, прав не даёт) ставит админ; он даёт уникальное достижение `platform-developer`.
- **Верификация аккаунта (галочка)** ([cortex/verification.ts](cortex/verification.ts)): порог — 365 дней на платформе, 500 импульсов и телефон. Заявка проходит этапы `submitted → scan → review → decision`; сканер прогоняет все навыки заявителя, любая находка — отказ. Галочку ставит только право `users.verify`, по заявке или вручную.
- **Профиль** `/u/[handle]`: аватар, обложка, био, организация, сайт, локация, профессия, счётчики, вкладки «О разработчике / Направления / Достижения», карточка друзей, тепловая карта активности. Ховеркарт пользователя при долгом наведении. `/authors/[owner]` перенаправляет на профиль, если хендл занят зарегистрированным аккаунтом.
- **Консоль** `/dashboard/*`: настройки, публикация и ключи, оплата, уведомления, администрирование (модерация, верификация), админ-панель (обзор, пользователи, краулер), публичный профиль.

### 13. Соцслой

- **Импульсы** — местный аналог лайка между пользователями, тумблер.
- **Друзья** ([cortex/friends.ts](cortex/friends.ts)): дружба — взаимный follow; односторонний — неотвеченная заявка. Уведомления о заявках и принятии.
- **Посты**: мини-грамматика ([lib/post-body.ts](lib/post-body.ts)) с блоками кода (подсветка на сервере, автоопределение языка), `inline code` и `@упоминаниями`; карусель до нескольких фото; реакции эмодзи (одна на пользователя).
- **Комментарии** к постам и навыкам.
- **Лента `/feed`** ([cortex/feed.ts](cortex/feed.ts)): вкладка «Для вас» ранжируется по `(1 + affinity) × quality × freshness × seen` (друзья, подписки, упоминания, импульсы, прошлые реакции, друзья друзей, похожие вкусы) с чипом причины показа; вкладка «Подписки» — хронология. Справа — «Кого добавить».
- **Скиллсеты** ([cortex/skillsets.ts](cortex/skillsets.ts)): наборы записей каталога, создаются только на платформе. История каждого изменения, избранное, картинки в описании, верификация (сбрасывается при изменении состава), установка одной командой. Раздел `/favorites` — свои и избранные скиллсеты и отслеживаемые записи.
- **Отслеживание навыков** (Watch): при выходе новой версии подписчики получают уведомление.
- **Уведомления** ([cortex/notifications.ts](cortex/notifications.ts)): входящие с табами «социальное / навыки / система», опрос раз в 20 с, тосты и звук (можно отключить), шторка в хедере и страница `/dashboard/notifications`.
- **Бейджи** ([types/badges.ts](types/badges.ts)): 13 достижений с артом — за первый навык и пост, импульсы, авторство, популярность, стаж и др. Все выдаются автоматически и идемпотентно (`evaluateBadges()`); ручная выдача предусмотрена через `grantBadge()`.

### 14. Сайт

- **Главная** — hero с ASCII-руками и манифест (бывший `/about`): телеметрия, «как это работает» с графом-синапсом из реальных записей каталога, принципы, популярное, CTA.
- **Хедер** — логотип, меню с мега-панелью и поиском (⌘K), блок пользователя. **Футер** — колонки ссылок и гигантский вордмарк.
- **FAQ**, глобальная 404, анимации входа с учётом `prefers-reduced-motion`.

### 15. Инфраструктура

- **Интерфейс на 4 языках**: en, ru, uk, zh (локаль в cookie, без префикса в URL).
- **Хранилище**: без `DATABASE_URL` всё работает в памяти, с ним — Prisma + PostgreSQL (Neon через Netlify DB). Схема синхронизируется `scripts/db-sync.mjs` при сборке.
- **Деплой**: Netlify (scheduled functions для краулера и продления), Docker/VPS, установщик `install.sh`.
- **Защита**:
  - ограничение частоты для каждой мутации и дорогого эндпоинта ([cortex/rate-limit.ts](cortex/rate-limit.ts));
  - защита от SSRF при запросах по пользовательским адресам ([cortex/ssrf.ts](cortex/ssrf.ts));
  - безопасная обработка пользовательских URL ([lib/url-safety.ts](lib/url-safety.ts));
  - CSP и заголовки безопасности;
  - CORS открыт только для публичного чтения каталога;
  - cron-эндпоинты закрыты секретом;
  - импорт не может перезаписать чужой навык.
- **Тесты**: 26 наборов — сканер, парсер, поиск, ранжирование, биллинг, платежи, шлюз, агентский API, ключи, краулер, безопасность, соцслой, друзья, лента, посты, скиллсеты, модерация, верификация, роли, регистрация, подтверждение почты, i18n и другие.

## Что заложено, но пока не доведено до конца

Эти вещи есть в типах, схеме базы или каталоге правил, но полноценного сценария для них нет:

| Возможность | Что есть | Чего нет |
|---|---|---|
| **Выплаты авторам** | Тип проводки `payout`, доход автору начисляется при каждом вызове | Периода pending → available (14 дней), вывода денег, споров |
| **Рубли в леджере** | Цены тарифов в рублях (копейки) | Кошелёк и цены вызовов пока в микродолларах — перевод ждёт подтверждения |
| **Динамическая песочница** | Правила DY-01…07, PI-08, EX-04, MC-09, OP-02 со статусом `planned` | Среды исполнения, canary-токенов, перехвата сети и файловой системы |
| **Внешние проверки** | Правила RM-02…06, SK-05 со статусом `planned` | Возраста домена, дрейфа `tools/list`, cloaking, OAuth-scope, секретов в истории коммитов |
| **LLM-слой** | Метод `llm` у PI-01/04/05, EX-06, SK-06 (сейчас паттерны), OP-05; формула `resolve_task` | Модели (YandexGPT / GigaChat / локальная) для сканера и извлечения намерений |
| **Организации** | `ownerPolicy()` — точка наследования политики; тарифы Team/Business | Модели организации, членства, заявок администратору (`approval_status`), `save_as_pack` |
| **Gov и On-prem** | Уровень `Gov`, `Certified` у паков, правило RM-06 | Критериев GV-\*, бандлов `.synb`, On-prem-режима |
| **Подпись контента** | Ed25519 (`SYNAPTH_SIGNING_KEY`) | Без ключа в env пара генерируется на процесс |
| **Рейтинг и отзывы** | Поле `stats.rating`, отчёты `report_outcome` | Отзывов людей |
| **История версий и сканов** | Модели `SkillVersion`, `SecurityScan` | Их в интерфейсе не видно |
| **Плагины** | Бейдж `five` считает плагины по категории `Plugin` | Самой категории |
| **Вход через GitHub и Google** | Провайдеры подключены | Включаются только при заданных ключах OAuth |
