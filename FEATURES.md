# Synapth — функционал и заложенные возможности

Synapth — маркетплейс навыков, инструментов и MCP-серверов для ИИ-агентов, построенный на Next.js 15. Он собирает навыки с GitHub, проверяет их на безопасность и выдаёт каждому готовую команду установки. Агент может сам найти и подключить навык через API, без браузера. Код разделён на две части: серверное ядро `cortex/` и клиентский слой `axon/`.

## Что уже работает

### 1. Каталог «навыков»

Всё, что можно подключить агенту, хранится как одна сущность `Skill` трёх категорий ([types/skill.ts](types/skill.ts)):

- **MCP** — MCP-сервер, локальный (stdio) или удалённый (SSE);
- **Prompt** — фрагмент системного промпта или `SKILL.md`;
- **Tool** — HTTP-эндпоинт с описанием инструментов для function calling.

У каждого навыка есть манифест: системный промпт, инструменты с JSON Schema, способ запуска, запрашиваемые права (network, filesystem, shell, env, clipboard), нужные переменные окружения и схема шагов исполнения (`flow`).

### 2. Сбор навыков с GitHub

[cortex/crawler.ts](cortex/crawler.ts) и [lib/github-parser.ts](lib/github-parser.ts):

- **Поиск репозиториев** по темам (`topic:mcp-server`, `topic:claude-skills` и др.) и по файлам `SKILL.md` через code search.
- **Разбор репозитория**: понимает `synapth.json`, `mcp-server.json`, `server.json` (формат MCP registry), `.mcp.json`, `tool.json`, коллекции `SKILL.md`, а если ничего этого нет — README с явными признаками навыка.
- **Повторный обход** трогает только новые репозитории: состояние хранится в `data/crawl-state.json`.
- **Запуск**: `npm run crawl`, панель на дашборде (только для админа) или `POST /api/v1/crawl`. Один репозиторий можно импортировать через `/api/v1/import/github`.

### 3. Проверка безопасности (Sandbox Scanner)

[lib/sandbox-scanner.ts](lib/sandbox-scanner.ts) проверяет манифест по каталогу правил из ТЗ: 9 групп, 62 правила (`RULE_CATALOG`, у каждого — уровень, метод и статус `active | partial | planned`). Нумерация — `PI-01`…`DY-07`, версия набора правил (`RULES_VERSION`) пишется в каждый отчёт.

- **PI-\*** — инъекции в промпты и отравление инструментов: переопределение инструкций (en/ru/zh), скрытый текст (нулевая ширина, Unicode Tags, bidi, HTML-комментарии), закодированные вставки (base64/hex/URL — декодируются и сканируются повторно), затенение чужих инструментов, сокрытие от пользователя, автозапуск, аномальная длина.
- **EX-\*** — утечка данных: приказ отправить данные на адрес, ссылки/картинки с данными в параметрах, приёмники (вебхуки, боты, туннели), параметры, выманивающие контекст.
- **MC-\*** — опасное исполнение: `curl | sh`, реверс-шеллы, `eval`/`pickle`, `shell=True`, деструктивные команды, закрепление в системе, обфускация, `sudo`, майнинг (→ Карантин).
- **SK-\*** — секреты (OpenAI/Anthropic, Yandex Cloud, GigaChat, AWS, GitHub, Slack, Google, Telegram, PEM, строки БД; энтропия > 4,5). Живые ключи блокируют публикацию.
- **OP-\*, ST-\*, RM-\*** — права (опасные сочетания), структура (невалидный манифест → Отклонён, `npx pkg` без версии, выдача себя за бренд, бинарники, лицензия), удалённые серверы без TLS.
- **DP-\*** — цепочка поставки: [lib/dependency-scanner.ts](lib/dependency-scanner.ts) (install-скрипты, тайпосквоттинг, нет lock-файла, dependency confusion) и [cortex/dependency-audit.ts](cortex/dependency-audit.ts) (уязвимости из OSV, молодые и непопулярные пакеты). Краулер и импорт собирают снимок в `GithubSource.audit`.

Оценка риска — `max(0, 100 − 60·crit − 25·high − 8·med − 2·low)`. Исход решают правила: **Отклонён** (не публикуется), **Карантин** (скрыт из каталога и API), **Sandbox** (есть high/critical), **Community**. `Verified` сканер не ставит никогда — только модератор, и только при оценке ≥ 85; новая версия наследует Verified, если не изменились права, промпты и описания инструментов. Поверх — уровень **Gov**; у паков (скиллсетов) — производный уровень **Certified** (`packTrust`).

### 4. Поиск и сортировка

- **Свой поисковый движок** без внешних сервисов ([cortex/search.ts](cortex/search.ts)): ранжирование BM25F с весами полей, стемминг, автодополнение, исправление опечаток, фасеты, подсветка совпадений.
- **Язык запросов**: `category:MCP is:verified lang:python author:… tag:… stars:>100 price:free "фраза" -слово`.
- **Сортировки** ([cortex/ranking.ts](cortex/ranking.ts)):
  - Trending — скорость установок × звёзды × удержание;
  - Hidden Gems — Verified, удержание ≥ 60 %, не больше 5k установок;
  - Recent — по дате;
  - Relevance — по релевантности.

### 5. API для агентов (AI-first)

Одни и те же операции по двум транспортам ([cortex/agent.ts](cortex/agent.ts)):

- **MCP-сервер `synapth-mcp`** — `POST /mcp` (Streamable HTTP, JSON-RPC: `initialize`, `tools/list`, `tools/call`).
- **REST** — `GET|POST /api/v1/agent/<tool>`, список инструментов — `GET /api/v1/agent`.
- **Обнаружение** — `/.well-known/synapth.json` (адреса, аутентификация, публичный ключ подписи) и `/llms.txt`.

Инструменты: `search` (без ключа — 30/мин с IP, без Sandbox), `resolve_task` (до 3 вариантов: пак ≥ 80 % покрытия, жадный набор в бюджете токенов без конфликтов, одиночный навык; формула 0,45·rel + 0,2·trust + 0,2·success + 0,1·retention − 0,05·tokens/budget; подбор — BM25F), `get_skill`, `get_pack`, `fetch_skill` (файлы с SHA-256, `contentHash`, подпись Ed25519), `install_plan`, `confirm_install` (сверка хешей → `integrity_mismatch`), `report_outcome` (раз в сутки; ключи младше 7 дней и ключи автора не влияют на рейтинг), `check_updates` (diff прав, `revoked`), `execute`.

Политика ключа применяется до поиска; каждый ответ несёт `pol`, каждая ошибка — код и подсказку агенту; `requiresApproval` + серверная `approvalCard` — ничего не ставится молча. Каждый вызов пишется в `AgentAuditLog` (журнал в «Публикация и ключи»).

Старый режим `GET /api/v1/skills` с `X-Agent-Request: true` ([cortex/agent-context.ts](cortex/agent-context.ts)) по-прежнему работает.

### 6. Установка в один клик

[axon/install.ts](axon/install.ts) генерирует команду установки под четыре клиента: Claude Code, Claude Desktop, Cursor и curl.

- **MCP** → `claude mcp add …` или JSON для `mcpServers`.
- **`SKILL.md` из GitHub** → `npx degit` в `.claude/skills/` или `.cursor/skills/`.
- **Промпт** → файл `SKILL.md` или правило `.cursor/rules/*.mdc`.
- **HTTP-инструмент** → вызов через платёжный шлюз.

Выбранный клиент запоминается в cookie.

### 7. Оплата за каждый вызов

[cortex/gateway.ts](cortex/gateway.ts) и `POST /api/v1/skills/:id/execute` (или `execute` в MCP):

- **Проверки до списания**: не Sandbox/Карантин, scope `skills:execute`, политика ключа, лимит на вызов и в сутки, аргументы по JSON Schema инструмента, баланс. Отказ ничего не стоит.
- **Резерв → списание или снятие резерва** ([cortex/billing.ts](cortex/billing.ts)): `hold` при открытии; на 2xx — `release` + три проводки (списание, доход автору, комиссия 15 %), иначе только `release`. Сумма проводок операции — ноль, баланс = сумма проводок.
- **`Idempotency-Key`**: повтор в течение 24 ч возвращает сохранённый ответ без повторного списания ([cortex/idempotency.ts](cortex/idempotency.ts)).
- **Шлюз**: только публичные адреса (`safeFetch`), таймаут 30 с, ответ до 1 МБ; тело чужой ошибки наружу не отдаётся.
- В `UsageEvent` пишутся ключ, статус апстрима, задержка и размер ответа.

### 7a. Synapth Pro: тарифы и оплата

- **Страница `/pro`** — Free / Pro / Team / Business (месяц или год), разовые проверки, лицензии On-prem ([types/billing.ts](types/billing.ts)).
- **Кабинет `/dashboard/billing`** — текущий тариф, расход квот за сутки, смена тарифа (выше — сразу с пропорциональным пересчётом, ниже — со следующего периода), отмена/возобновление, пополнение кошелька, история оплат.
- **Платёжные шлюзы** ([cortex/payment-providers.ts](cortex/payment-providers.ts)): ЮKassa (карта, СБП, сохранённый способ для продления), CloudPayments (HMAC вебхуков), mock-страница для разработки. Редирект на страницу провайдера → возврат на `/dashboard/billing/return` → вебхук `/api/v1/billing/webhook/<provider>`; применение платежа идемпотентно ([cortex/payments.ts](cortex/payments.ts)).
- **Продление** — `POST /api/cron/billing` (Netlify: `billing-cron.mjs`, раз в сутки): списание сохранённым способом, иначе `past_due` → 14 дней льготы → Free.
- **Квоты тарифа** ([cortex/plans.ts](cortex/plans.ts)): ключи, запросы агента и `resolve_task` в сутки, срок хранения журнала.

### 8. Страница навыка

- README в markdown;
- граф исполнения (trigger → tools → decision → output);
- построчный diff системного промпта до и после установки;
- отчёт сканера;
- спецификации инструментов;
- обсуждение.

### 9. Аккаунты и профили

- **Вход**: Auth.js v5 — GitHub, Google и логин с паролем (bcrypt). Роли `user` и `admin`.
- **Профиль** `/u/[handle]`: аватар, обложка, био, организация, сайт, локация, профессия. Есть тепловая карта активности.
- **Страницы GitHub-авторов** `/authors/[owner]` перенаправляют на профиль, если такой пользователь зарегистрирован.
- **Консоль** `/dashboard`: кошелёк, публикация навыка, панель краулера, ключи, настройки, уведомления.

### 10. Соцслой

- **Импульсы** — местный аналог лайка между пользователями, включается и выключается.
- **Посты и комментарии**; комментировать можно пост или навык.
- **Отслеживание навыков** (Watch): при выходе новой версии подписчики получают уведомление.
- **Уведомления**: входящие с табами «социальное / навыки / система», опрос сервера раз в 20 с, всплывающие сообщения и звук (можно отключить).
- **Бейджи**: 13 штук — за первый навык, за Verified-публикации, за авторство MCP/Prompt/Tool, за импорт с GitHub, за активность. Большинство выдаются автоматически, `early-adopter` — только вручную админом.

### 11. Инфраструктура

- **Интерфейс на 4 языках**: en, ru, uk, zh (локаль хранится в cookie).
- **Без `DATABASE_URL`** всё работает в памяти, с ним — Prisma + PostgreSQL.
- **Установщик** `install.sh` и конфигурация для деплоя на Netlify.
- **Защита**:
  - ограничение частоты для каждой мутации;
  - защита от SSRF при запросах по пользовательским адресам;
  - безопасная обработка пользовательских URL;
  - CSP;
  - CORS открыт только для публичного чтения каталога;
  - импорт не может перезаписать чужой навык.
- **Тесты**: 11 наборов — сканер, парсер, поиск, ранжирование, биллинг, краулер, безопасность, соцслой, i18n и другие.

## Что заложено, но пока не доведено до конца

Эти вещи есть в типах или схеме базы, но полноценного сценария для них нет:

| Возможность | Что есть | Чего нет |
|---|---|---|
| **Рубли в леджере** | Цены тарифов в рублях (копейки) | Кошелёк и цены вызовов пока в микродолларах — перевод ждёт подтверждения |
| **Вывод денег автору** | Тип записи `payout` | Периода pending → available (14 дней), выплат, споров |
| **LLM-подбор в `resolve_task`** | Формула ранжирования, BM25F | Извлечения намерений через YandexGPT / GigaChat / локальную модель |
| **Динамическая песочница, AST, внешние базы** | Правила DY-\*, RM-02…06, EX-04, MC-09, OP-02, OP-05, SK-05 в каталоге со статусом `planned` | Исполнения |
| **Организации** | `ownerPolicy()` — точка наследования политики | Модели организации, заявок администратору (`approval_status`), `save_as_pack` |
| **Gov и бандлы** | Уровень `Gov`, `Certified` у паков | Критериев GV-\*, бандлов `.synb`, On-prem-режима |
| **Подпись контента** | Ed25519 (`SYNAPTH_SIGNING_KEY`) | Без ключа в env пара генерируется на процесс |
| **Рейтинг и отзывы** | Поле `stats.rating`, отчёты `report_outcome` | Отзывов людей |
| **История версий и сканов** | Модели `SkillVersion`, `SecurityScan` | Их в интерфейсе не видно |
| **Вход через GitHub и Google** | Провайдеры подключены | Включаются только при заданных ключах OAuth |

## Итог

Ядро маркетплейса работает: сбор с GitHub, проверка по каталогу из 62 правил, поиск, установка, агентский API по MCP и REST с политиками и журналом, платёжный шлюз с резервированием и подписки Synapth Pro. Не хватает рублёвого леджера, выплат авторам, LLM-подбора, динамической песочницы и организаций.
